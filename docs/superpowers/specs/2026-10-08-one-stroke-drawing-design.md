# STM32F407 双轴一笔画作画功能设计

**状态：待用户审阅**  
**日期：2026-10-08**

## 1. 目标

在现有 STM32F407ZGT6 双轴步进点动固件上增加触摸屏作画功能：用户先用现有点动方式将机构和笔尖放在机械中心，再在触摸屏上单指连续画出一笔；抬手后检查并预览轨迹，用户明确按下“开始”后，X/Y 两轴协同驱动笔尖按该轨迹运动。

保留原有点动页和按键行为。作画行程相对用户确认的中心定义：X 为 ±3500 steps，Y 为 ±2300 steps。该限值是固件软限位，不是位置反馈或机械限位。

## 2. 已确认的现状与约束

- `User/ui/ui_task.c` 是唯一 UI 任务；LCD 初始化后显示电机页，循环周期为 50ms。
- GT9xx 坐标读取在 UI 任务上下文执行；触摸中断只置标志。当前 GT9xx 接口保留最新坐标，抬手会清除触摸标志，没有可供画笔使用的完整按下/移动/抬起事件流。
- 当前触摸按钮处理带有 200ms 消抖，不适用于连续轨迹采集。
- `User/task/motor_task.c` 以 10ms 周期扫描按键并运行单轴点动状态机。
- `User/motor/bsp_motor.c` 用 TIM2_CH2/CH3 硬件 PWM 输出两路 STEP，基础周期为 1ms，更新中断只统计正在输出的轴的步数；当前没有双轴轨迹插补接口。
- X 轴为 PA1/TIM2_CH2 + PA15/DIR；Y 轴为 PA2/TIM2_CH3 + PA14/DIR。PA14 与 SWCLK 复用冲突，现有 OpenOCD 复位下连接约束必须保留。
- 工程没有回零开关、编码器或丢步检测。固件无法知道上电后的绝对机械位置，也不能从软件确认物理中心。
- LCD 是 480×800，使用 ASCII 英文字库绘制。

## 3. 方案选择

采用**整笔缓冲、运动前校验、屏幕预览、用户确认后播放**。不采用手指触摸时同步驱动电机，因为那不能预先验证整条路径；也不采用各轴独立脉冲，因为它不能保证斜线/曲线上的两轴步进比例。

## 4. 用户交互流程

1. 上电进入现有点动页；用户用 KEY1/KEY2 将机构和笔尖手动放到所需中心位置。
2. 点击新增的独立 `DRAW` 按钮进入作画页。若点动仍在运行，拒绝进入。
3. 用户点击 `CENTER READY`，声明当前物理位置为本次作画的 (0,0)。每次新作画都必须重新确认中心；不能因上一次软件步数而推断用户没有手动移动机构。
4. 用户在画布内用单指画一条连续轨迹。第二个触点、离开画布、触摸 I²C/轨迹容量错误都会使本笔无效，不得启动电机。
5. 抬手结束轨迹并进入预览。预览显示映射到机器坐标后的路径、越界/有效状态和 `START`、`REDRAW`、`CANCEL` 控件。无效轨迹没有可用的 `START`。
6. 用户按 `START` 后播放。播放过程中屏幕显示 `STOP` 和状态；用户可以请求停止。播放结束后保持在结果页，显示完成或中止；再画一笔前重新手动置中并确认。若请求在电机尚未开始运动前被拒绝（例如按键仍按住），显示拒绝原因；用户修正原因后可以重试同一预览，不要求重新置中，因为机械位置没有被作画运动改变。
7. 取消、重画、返回点动页不会自动移动电机。播放期间忽略轴选择和新的轨迹提交。

## 5. 坐标与轨迹语义

### 5.1 单笔定义及起点

一笔指 GT9xx 单指的一次按下至抬起序列。机器没有 Z/抬笔执行器，故不能先从机械中心空走到任意首点而不留下线。为避免预览路径与实际落笔路径不一致，**首个有效触摸点定义为机器中心 (0,0)**；之后每个点都转换为相对首点的 X/Y 位移。预览把该起点绘制在画布的中心参考标记上，因此整个图形相对于手指在原画布上的绝对位置平移，但形状、方向和比例保留。机器从已确认的物理中心直接开始，不增加首点连接线。

如果产品必须让手指在画布中的绝对位置也对应纸面绝对位置，或必须支持自动抬笔/落笔，则需要增加本设计范围之外的笔升降硬件；当前实现不假设有该硬件。

### 5.2 比例与极性

- 工作区保持 X/Y 物理行程比例，依据宽高步数范围 7000:4600 计算，在 480×800 竖屏中居中留白；不分别拉伸 X、Y 以填满整块屏幕。
- 触摸屏向右映射为逻辑 +X，向上映射为逻辑 +Y。两轴 DIR 电平极性通过独立配置常量确定；由于仓库代码不能证明实机接线方向，首次硬件验证必须低速确认方向。方向未确认前不得以正式速度作画。
- 以整数定点/有符号整数完成坐标换算和插补，避免在中断中使用浮点运算。
- 将整条轨迹换算为以中心为原点的有符号步数后，逐点检查 X ∈ [-3500,3500]、Y ∈ [-2300,2300]。线段端点均在矩形范围内即可保证该直线插值也在范围内。任何越界整笔拒绝，不裁切、不部分执行。
- 限值集中定义为可调整配置。它只约束固件已知的相对命令位置；中心摆放误差、手动移动、失步和机械行程偏差仍可能造成物理越界。

### 5.3 采样容量

- 作画采集和播放期间 UI 任务按不大于 10ms 周期处理触摸；现有普通页面按钮消抖不用于轨迹点。触摸读取失败若发生在采集中，当前笔立即标为无效，不能跨越丢失区间继续连线。
- 使用固定容量 2048 个转换后的有符号 X/Y 轨迹点（约 8KiB），去除连续重复步点；不动态分配堆内存。
- 缓冲区满时立即将当前笔标为无效，不能静默截断后仍允许启动。
- 坐标缓冲区只允许在采集/预览期间由 UI 写入；提交播放后冻结，直到播放器完成或中止。

## 6. 软件结构与数据流

### 6.1 UI 与触摸

- `User/ui/ui_task.c` 增加页面/作画状态机：点动页、等待中心确认、采集中、预览、播放中、完成/中止/错误。
- `User/ui/ui_draw.c` 增加 `DRAW` 入口、比例画布、中心标记、实时轨迹/预览、操作按钮及状态提示；页面文字保持 ASCII。
- `User/touch/gt9xx.c/.h` 增加可从任务上下文读取的单指触摸状态/事件接口，使 UI 能可靠区分按下、移动、抬起并发现多指；不在 ISR 中访问 LCD 或执行电机控制。
- 保留原点动页的点击、200ms 按钮消抖和触摸处理中断边界，不让作画采样规则意外改变普通 UI 行为。

### 6.2 几何/路径核心

新增独立的纯 C 轨迹核心模块（例如 `User/plotter/plotter_path.c/.h`），负责：触摸像素到相对步数的比例映射、重复点压缩、全路径软限位验证，以及将折线分解为确定性的整数直线步进段。该模块不得依赖 STM32 寄存器、LCD 或 µC/OS API，便于主机测试。

### 6.3 运动所有权与插补

- 电机外设只能由电机控制侧拥有；UI 通过固定容量轨迹邮箱/命令接口提交只读轨迹，不直接写 TIM2/GPIO。
- 扩展 `Motor_Task` 的工作状态，使其在原 10ms 按键扫描职责之外管理作画命令、运行/停止状态；作画时禁止点动与轨迹播放并行。
- TIM2 仍以 1kHz 更新事件作为共同时间基准。作画运动引擎使用整数 DDA/Bresenham 插补决定每个时间片应由 X、Y 或两轴发步，并用软件分频限制最高步频；利用 TIM2_CH2/CH3 硬件 PWM 输出完整 STEP 脉冲。更新中断只做有界的整数插补、方向建立等待、脉冲调度和已生效脉冲计数/状态更新，不调用阻塞函数或 LCD。对预装载 CCR，计数按对应输出周期生效时更新，避免把尚未输出的待发脉冲记入位置。
- 作画步频由集中配置的 `PLOTTER_STEP_RATE_HZ` 限制，初始值为 250 steps/s，且不得超过现有 1kHz 基础步频；轴方向变化时至少等待 `MOTOR_DIR_SETUP_TICKS` 对应时间后再发新方向的 STEP。脉冲宽度遵循现有 CCR 配置。若实机在此速率下失步，需先降低配置步频再继续硬件验收；未通过低速实机检查前不宣称轨迹精度已验证。
- 现有 `Motor_UpdateISR()` 同时支持点动计步与作画逐轴 DDA；DDA 对每条线段精确发出其 X/Y 整数步数，完成后关闭两通道输出，路径终点成为本次软件相对位置。
- 运行期间收到 STOP，将停止请求交给定时器运动引擎，在不再安排后续 STEP 的首个安全更新边界关闭输出，并报告中止。停止响应受触摸轮询/任务调度延迟影响；它不是硬件急停，也不能消除机械惯性。

### 6.4 位置有效期

中心确认只对随后的一次播放建立逻辑原点，并在 START 被接受时消费。播放正常结束或中止后均清除中心确认；任何人工移动、复位或断电也会使逻辑位置失效。因此每次播放前都必须重新执行中心确认；固件不跨复位保存坐标，不允许以旧坐标绕过确认。预览页 REDRAW 若尚未开始播放，可沿用本次有效中心。

## 7. 错误处理与安全不变量

- 未确认中心、空笔、越出画布、越过步数软限位、多指、触摸/轨迹缓冲错误：保持 STEP 静止，显示明确错误，可重画或取消。
- PENDING/RUNNING 播放命令只接受一次；播放中不接受重复 START、轴切换、点动或第二笔。未启动电机而进入 REJECTED 的请求可在修正拒绝原因后重新提交；STOP 与资格拒绝并发时，已发布的 STOP 优先映射为 ABORTED，不得被 REJECTED 清除。
- 故障异常路径继续在死循环前调用 `Motor_StopAll()`；不能删除现有停脉冲保障。
- 整条轨迹必须在运动前校验通过；运动引擎不允许接受未校验数组或越界段。
- TIM2 ISR 不得调用 RTOS 阻塞 API、LCD、串口打印或 bit-bang I²C。
- 停止或错误后清空待播放/待发脉冲状态，不能因旧 CCR 或旧命令自动继续运动。
- 软限位不是实体安全装置。无限位开关/编码器时，无法检测机构已经撞限位或漏步；使用前需确认机构可用行程、中心和方向。

## 8. 验收标准

### 主机自动化验证

1. 坐标原点、四方向映射、整数舍入、长宽比例符合定义。
2. ±X/±Y 边界被接受；任一越界点使整笔被拒绝；整笔拒绝不产生部分播放命令。
3. DDA 对水平、垂直、正/反斜线产生精确端点和精确各轴步数；两轴步数比例误差不超过标准整数 Bresenham 的 1 步界限。
4. 重复点、短线、最大点数和缓冲区溢出均有确定行为；溢出不能播放。
5. UI/电机状态契约：无 START 不运动；运行中 START/切轴/点动无效；STOP 最终将两通道关闭。
6. 原有静态契约测试继续通过。

### 固件与硬件验证

1. `./build.sh` 成功，链接内存仍在 STM32F407ZGTx_FLASH.ld 定义的 RAM/Flash 范围内。
2. 烧录后先在机构可安全活动的区域，以低速分别验证 X/Y 正负方向、软限位方向和停止动作；确认 PA14/SWCLK 的复位下连接流程仍可用。
3. 用示波器/逻辑分析仪确认 STEP 脉冲宽度、两轴 DDA 脉冲数和方向建立时间；用已知方形/对角线测试确认屏幕预览与实体轨迹方向、比例一致。
4. 只有完成上述实机检查，才可把端到端作画准确性标为已验证。当前没有目标板/机构的自动化仿真环境。
